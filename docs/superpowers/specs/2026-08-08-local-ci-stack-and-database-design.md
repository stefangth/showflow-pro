# Local CI stack + local database — design

**Date:** 2026-08-08
**Status:** Approved (brainstorm), pending spec review
**Branch:** `claude/local-ci-stack-database-5a3ca3`

## Problem

Agents (and developers) working in this repo have no local database. The only
env wiring, `scripts/link-dev-env.sh`, symlinks each worktree's `.env` to the
main checkout's `.env`, which points at **live production**
(`epweartpzwvcasrzyueh.supabase.co`) with autologin as the prod super-admin. So
`npm run dev` and any local Playwright run **mutate real customer data**.

Meanwhile the entire local stack already exists and is proven green in CI
(`.github/workflows/ci.yml`): `supabase/config.toml`, ~195 migrations,
`seed.sql`, pgTAP tests, the Deno suite, and Playwright specs. CI boots a local
Supabase stack on Linux for db-tests and e2e. **Nothing about that stack has
ever been made runnable on a developer's Mac, and the committed default points
the app at prod.**

Goal: make the full CI stack + a local Supabase database runnable locally, with
the **committed default pointed at LOCAL and production demoted to an explicit
opt-in**, so agents can develop and test without touching production.

## Decisions locked in brainstorming

1. **Local data = synthetic seed only.** No production clone, no anonymization
   pipeline. `seed.sql` already creates three login-ready users
   (`admin@example.com`, `producer@example.com`, `artist@example.com`, password
   `showflow-dev`) and `supabase start` applies it automatically. Zero PII,
   byte-identical to what CI runs.
2. **Approach B — flip the committed default to local; prod becomes opt-in.**
   `npm run dev` → LOCAL by default in every worktree; `npm run dev:prod` → prod.
3. **Container runtime = OrbStack** (fast, light on Apple Silicon, drop-in
   Docker). The only prerequisite the developer installs by hand.
4. **Two-tier local test convention:** `verify:fast` (Docker-free inner loop)
   and `verify:full` (boots the stack, adds pgTAP + e2e — the pre-PR-to-main
   gate). Mirrors how CI itself is split (most jobs run on every push; e2e runs
   only on PRs targeting `main`).

## Non-goals (YAGNI)

- No production data clone; synthetic seed only.
- No local edge-function secrets wiring (RESEND / Documenso / ANALYTICS / cron
  secret). Flows that require them are out of scope and simply unset locally;
  the runbook says so.
- No devcontainer / VM image.
- **No changes to CI workflows, migrations, or the schema.** We only make the
  existing stack runnable locally.

## How the env flip works

Vite resolves `.env` files by **mode**, and mode-specific files win over generic
ones for the same key. `.env` and `.env.*` are already gitignored
(`.gitignore:28-30`), except `.env.example`.

- `npm run dev` runs in **development** mode → a **committed `.env.development`**
  (local) overrides the prod-pointing `.env` symlink.
- `npm run dev:prod` = `vite --mode prod` → does **not** load `.env.development`,
  so it falls back to the gitignored `.env` (prod).

Key safety property: a brand-new worktree that ran no setup **cannot silently
hit prod** — its committed default is `127.0.0.1`. If the local stack is not
running, the app fails to reach localhost (a loud, safe failure) instead of
quietly mutating production.

Committing local values is safe: the local URL and anon key are the **standard
published local-dev constants** (the anon key is a public client key by design —
prod ships it in the browser bundle too). The **service-role key is never
committed**.

Production builds (Vercel) run in **production** mode and never load
`.env.development`; autologin is `import.meta.env.DEV`-guarded and stripped from
prod builds. So the flip is invisible to production.

## Components

### 1. Env files

- **`.env.development`** — committed, via a `!.env.development` exception in
  `.gitignore`. Contents:
  - `VITE_SUPABASE_URL=http://127.0.0.1:54321`
  - `VITE_SUPABASE_PUBLISHABLE_KEY=<standard local anon key>` (verified against
    live `supabase status` during implementation)
  - `VITE_SUPABASE_PROJECT_ID=local`
  - `VITE_DEV_AUTOLOGIN=true`
  - `VITE_DEV_AUTOLOGIN_EMAIL=admin@example.com`
  - `VITE_DEV_AUTOLOGIN_PASSWORD=showflow-dev`
- **`.env.development.local`** — gitignored (matched by `.env.*`), generated by
  `local:up`. Carries the live `SUPABASE_SERVICE_ROLE_KEY` (for e2e setup/
  teardown) and re-asserts `VITE_SUPABASE_PUBLISHABLE_KEY` / `SUPABASE_URL` from
  live `supabase status` in case the constant ever drifts. Highest priority in
  dev mode, so it always corrects the committed defaults. **Service-role key
  never committed.**

### 2. Package.json scripts

- `dev:prod` → `vite --mode prod` (the prod opt-in path).
- `local:up` → `bash scripts/local-up.sh`.
- `local:down` → `supabase stop`.
- `local:reset` → `supabase db reset` (re-apply migrations + reseed; wipes local
  data).
- `local:setup` → `npx playwright install chromium` (one-time; no `--with-deps`
  on macOS).
- `test:functions` → **fix to** `deno test --allow-all --node-modules-dir=none
  supabase/functions/` (currently missing the flag, so it fails locally — the
  root `package.json` forces Deno into node_modules mode; CI already uses the
  flag).
- `verify:fast` → `bash scripts/verify.sh --fast`.
- `verify:full` → `bash scripts/verify.sh --full`.

### 3. `scripts/local-up.sh`

1. Guard: `docker info` — if the daemon is unreachable, print "Start OrbStack (or
   your Docker runtime), then re-run `npm run local:up`." and exit non-zero.
2. `supabase start` (idempotent — a no-op if already up; first boot applies all
   migrations + `seed.sql`, so the three logins are immediately usable).
3. `eval "$(supabase status -o env)"` → read `API_URL`, `ANON_KEY`,
   `SERVICE_ROLE_KEY`.
4. Write `.env.development.local` with `SUPABASE_URL`,
   `SUPABASE_SERVICE_ROLE_KEY`, `VITE_SUPABASE_URL`,
   `VITE_SUPABASE_PUBLISHABLE_KEY` (live values).
5. Print next steps: open `http://localhost:8080`, the three logins, and the
   `verify:*` / `local:down` commands.

### 4. `scripts/verify.sh --fast|--full`

Runs each layer as a step, **continues past failures**, prints a summary table
of pass/fail/skip at the end, and exits non-zero if any layer failed (loud
reporting — a skipped or failed layer never reads as a pass).

- **`--fast`** (no Docker): `lint` (eslint + `sync:mirrors:check`) → `tsc -p
  tsconfig.app.json --noEmit` → `tsc -p tsconfig.tools.json --noEmit` → `build`
  → `test:coverage` → `deno check --node-modules-dir=none
  supabase/functions/*/index.ts` → `test:functions`.
- **`--full`**: `local:up` (idempotent; skips the Docker-gated layers with a loud
  notice if the runtime is down) → everything in `--fast` → `test:db` (pgTAP) →
  `test:e2e` (Playwright).

`--full` does **not** tear the stack down (leave it up for the dev loop); use
`local:down` when finished.

### 5. E2E local env loading

Playwright's local `webServer` runs `npm run dev` (Vite reads `.env.development`
+ `.env.development.local`), but `e2e/global-setup.ts` reads `process.env
.SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`, which Vite's file loading does not
populate. Fix: load `.env.development.local` (and `.env.development`) into
`process.env` at the top of `playwright.config.ts`, **filling only keys not
already set**. CI has no such file and injects these via `GITHUB_ENV`, so the
"only-if-unset" rule keeps CI unaffected.

### 6. Dev-server target banner

A tiny Vite plugin in `vite.config.ts` (serve mode only) that logs one line on
dev startup from the resolved `VITE_SUPABASE_URL`:
`▶ Supabase: LOCAL (127.0.0.1:54321)` or
`▶ Supabase: PRODUCTION (epweartpzwvcasrzyueh)`. Non-blocking; makes `dev` vs
`dev:prod` unambiguous for humans and agents.

### 7. Guard test

`scripts/localEnv.test.mjs` (node, mirrors `scripts/seedUuidIsolation.test.mjs`)
asserting:
- `git check-ignore` ignores `.env.development.local` but **not**
  `.env.development` (the committed default stays tracked).
- `.env.development` targets `127.0.0.1` and contains **no** production project
  ref (`epweartpzwvcasrzyueh`) — the committed default can never silently be
  prod.

### 8. Docs

- **`docs/runbooks/local-development-stack.md`** — the full flow: install
  OrbStack → `npm run local:setup` (once) → `npm run local:up` → `npm run dev`
  (local) / `npm run dev:prod` (prod) → `verify:fast` / `verify:full` →
  `local:down` / `local:reset`. Includes the logins table, the flip explanation,
  the note that edge-function secrets are unset locally, and troubleshooting
  (Docker down, port conflicts on 54321/54322/8080, stale volume → `local:reset`,
  CLI version drift vs the CI-pinned 2.98.2).
- **CLAUDE.md** — a short "Running locally against a local database" subsection
  under Build/test/lint pointing at the runbook, plus a one-line note that
  `npm run dev` now defaults to local and `dev:prod` is the prod opt-in, so
  agents discover the flow.

## What changes for the developer

`npm run dev` in the **main checkout** now targets **local**, not prod. To dev
against prod as super-admin (the current habit), run **`npm run dev:prod`**. This
is the deliberate trade of "flip the default," and the banner makes the active
target explicit on every dev start.

## Risks / edge cases

- **Vite precedence** — the plan must verify empirically that `.env.development`
  beats the symlinked `.env` in dev mode (expected, but confirm on a real
  `npm run dev`).
- **Anon-key drift** — mitigated by `local:up` writing the live anon key into
  `.env.development.local` (which overrides the committed constant), plus the
  guard test ensuring the committed default is at least local, never prod.
- **Port conflicts** (54321/54322/8080) — `supabase start` errors clearly;
  documented in the runbook.
- **Owner muscle memory** — `dev` now local; documented prominently and made
  explicit by the banner.
- **CLI version drift** — local 2.109.1 vs CI-pinned 2.98.2; noted in the
  runbook, not a blocker (pin later if pgTAP/migration behavior ever diverges).

## Testing strategy

- **Guard test** (§7) runs in `verify:fast` via the existing `scripts/*.test.mjs`
  vitest/node path, so a regression that re-ignores or re-points the committed
  default fails CI.
- **The scripts are validated by running them** end-to-end once OrbStack is up:
  `local:up` → `dev` (banner shows LOCAL, autologin lands) → `verify:full` green.
- No new production code paths; nothing to unit-test beyond the guard.
